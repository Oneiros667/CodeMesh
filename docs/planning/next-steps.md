## Product Boundary

The initial wedge remains source-grounded implementation discovery, likely
change-impact navigation, and validation selection for C#/.NET coding agents.
Correctness, safety, freshness, and attributable agent outcomes take precedence
over broader feature coverage.

Owner direction has activated a bounded one|nine adoption priority alongside
that wedge. It adds the Rust and Python coverage needed to index one|nine,
repository-specific onboarding across its isolated checkouts, and a durable
feedback path from one|nine agents to CodeMesh development. This activation does
not authorize general parser expansion or make diagnostic feedback product-
benefit evidence.

Do not select broad parser, SDLC, UI, model-provider, summary, portability,
snapshot, shared-store, or agent-memory work merely because it is documented.
Activate it only when the ordered work below or explicit owner direction does
so.

## Current Execution Order

The checkout-safe integration, atomic Python-plus-Rust ingestion, Rust parser,
feedback loop, instance-owned onboarding, and configured provider-free Primary
gate are implemented. Corrected clean candidate `0378740`, exact Primary commit
`fe2f761`, the configured preflight, the frozen one|nine pilot, and the
YoutubeDownloader live gate all pass provider-free. The full deterministic
checks also pass at that candidate. The first authorized configured model
campaign remains frozen at historical candidate `0bde606`. The separately
authorized campaign through corrected candidate `0378740` also completed three
correct and safe pairs but remained insufficient: one treatment called status,
no treatment retrieved context, and there were no CodeMesh-attributable wins.
The next three priorities are:

1. **Verify the implemented one-step entry correction.** The normal-host MCP
   instructions, repository-owned onboarding, and tool descriptions now select
   the fail-closed `codemesh_get_context_package` operation as the single first
   action while retaining repository status for explicit diagnostics. Preserve
   prompt parity, create a new exact clean candidate, and pass the full
   deterministic and exact provider-free gates.
2. **Remeasure only after a new authority gate.** With separate explicit
   model-spend authority, rerun the pinned one|nine paired task through a new
   exact clean candidate and the same Primary source identity. Keep task prompt,
   model settings, grading, control behavior, normal-profile guidance, and
   permitted Graphify baseline fixed. Require actual context retrieval before
   attributing timing, token, correctness, or validation differences to
   CodeMesh.
3. **Replicate and decide bounded expansion.** Only after a valid one|nine
   context-adopting result, repeat configured/onboarded evaluation on Config.Net.
   Expand onboarding to Secondary, Tertiary, Release, or Hotfix only with a
   separate exact binding and passing checkout-specific probe. Keep Run-only
   excluded pending a separate acceptance decision.

After those priorities, use the implemented summary-model qualification runner
to qualify a complete deployment profile before summaries are considered for
default retrieval. Maintain the implemented default secret-file exclusion and
configurable ingestion path policy before broad artifact ingestion or shared
proprietary workspace storage.

Defer method-load and retrieval-granularity analysis, Kubernetes/Helm, parser
breadth beyond the activated Python/Rust pilot, UI expansion, outcome memory,
portable snapshots, shared stores, and broader SDLC ingestion until
configured/onboarded product benefit is repeatable or explicit owner direction
reprioritizes them.

The evidence supporting this order is summarized in
[Project Status](../current/project-status.md). Exact evaluation commands and

## Work Selection Rules

- Reconcile this order with current Git state, implementation, and retained
  evidence before choosing work.
- Treat fixtures, unit tests, configured workflows, local smoke runs, and
  historical reports as their stated evidence types only.
- Prefer the smallest change that addresses a measured failure or overhead.
- Keep generated summaries optional and provider-free evaluation available.
- Preserve frozen control/treatment prompts, grading, pinned repositories, and
  negative evidence when comparing changes.
- Do not lower gates, alter frozen tasks, or add treatment-only guidance to
  manufacture a favorable prompt-parity result.
- Record consequential implemented architecture decisions in `docs/decisions/`;
  proposals alone do not require an ADR.
